# terminal-ui-palette — Decisions
Last updated: 2026-11-16

Append-only. A decision is never edited or deleted: a replacement takes the next free id and
names what it supersedes. Dated per entry; `binds` lists the plan items it constrains.

## Decisions
- 2026-11-16 — D1 Render stack: ratatui 0.30 + crossterm, confined to `tuipalette-tui`; components render into `&mut Buffer` and never touch `Frame`, so they stay testable headless and backend-agnostic. Why: ratatui gives the diffing cell buffer, the constraint-based layout engine and a `TestBackend` for snapshots — the three things this project would otherwise have to invent. Binds all.
- 2026-11-16 — D2 No daemon in v1: one process per invocation, stdin/stdout contract, latency debt recorded rather than pre-paid. Why: a resident surface reintroduces terminal-specific code (kitty overlay, quick-access) and would be built before a single picker runs. Revisited only by 09's numbers. Binds 07, 09, 10.
- 2026-11-16 — D3 Placement is the host's: the core never positions, sizes or styles a window; the adapter (compositor rule for floating, the terminal itself for inline) owns geometry. Why: no terminal protocol can be asked to place a window, and pretending otherwise is how this project would fail. Binds 08, 09.
- 2026-11-16 — D4 Declarative spec, not a scripting language: a data document only — no conditionals, no expressions, no templating, no embedded runtime. Anything dynamic is a provider writing lines to stdin. Why: the spec must stay validatable and diffable, and a picker config is not the place to grow an interpreter. Binds 03, 11.
- 2026-11-16 — D5 Extension is a trait, not a plugin ABI: built-in components only in v1; adding one means a compile. Why: a stable external plugin boundary would have to be designed against zero real components. Binds 05, 11.
- 2026-11-16 — D6 Spec format: RON as the hand-authored format, JSON as the machine format, both behind one `spec::Format` adapter; TOML and KDL both dropped. Why: RON is serde-native with no mapping layer, its enum/struct syntax mirrors the spec's own split tree and variants instead of approximating them, comments are supported, and it is maintained (`ron 0.12.3`). JSON stays because a provider script can emit it with no dependency. Revised 2026-11-16: first recorded as KDL; the user vetoed it for RON. Binds 01, 03, 11.
- 2026-11-16 — D7 Shipped layouts are data, never library code: `layouts/*.ron` are user-space artifacts the crates do not reference; rofi parity must be a customer of the schema, not a property of it. Why: if the schema can only express a rofi-shaped picker, it cannot express the general one — which is the reason the project exists. Binds 03, 10, 13, 14.
- 2026-11-16 — D8 Key-map merge: per-pane entries win over the global map, global entries apply wherever a pane does not override them, and an explicit `none` clears an inherited bind. Why: global defaults keep simple specs short, and the explicit unset is what makes "not here" expressible without a second config file. Binds 04, 11.
- 2026-11-16 — D9 Names: project `terminal-ui-palette`; crates `tuipalette-core`, `tuipalette-tui`, binary `tuipalette`. Why: `palette` and `palette-core` are already taken on crates.io by the colour library, so the short prefix is not available; these three are free. Binds 02, 11.
- 2026-11-16 — D10 Two hosts, no compositor assumption: floating (compositor-placed terminal window) and inline (`Viewport::Inline` in the invoking terminal) are both first-class; muxer popups stay benched. Why: the keybind case wants a floating card, and every CLI case already has a terminal, so neither host may be the only path. Binds 07, 08, 09.
- 2026-11-16 — D11 Icons are a slot with a fallback, not a graphics feature: one declared-width slot per item, provider-supplied text, grapheme-width checked, placeholder on any failure; image protocols excluded. Why: it keeps rendering terminal-agnostic while still showing icons where the font provides them, and degradation is a layout promise rather than a per-terminal branch. Binds 05, 11, 15.
- 2026-11-16 — D12 Line protocol: one item per line, up to three TAB-separated fields — display text, value, icon — with trailing fields optional and a line carrying no TAB treated as both display and value, the way dmenu does it; icon lookup and escaping stay the provider's job. Why: it keeps the dmenu contract recognisable while giving icons and hidden values somewhere to live, and it costs a provider script one `printf`. Binds 06, 07, 15.
- 2026-11-16 — D13 Matcher default: `nucleo-matcher` ships as the default scorer, with `simple.rs` as the `--no-default-features` path. Why: the current rofi config already asks for fzf-style sorting, so fzf-compatible ranking is parity rather than taste; the crate is scoring-only — no UI, no worker pool — so none of the picker itself moves into it. Binds 06.
- 2026-11-16 — D14 Measurement basis: the 100 ms budget covers exec of the binary to the first flushed frame, with terminal spawn excluded; spawn and whole-path latency are reported separately and compared against rofi's whole path. Why: spawn is the compositor's and terminal's cost and mixing it in would make the number unfixable by this project — but reporting only our part would flatter us beside rofi, so both numbers are recorded. Binds 09, 12.
- 2026-11-16 — D15 Field sanitation, extending D12: display text is sanitized (TAB, CR, LF to a space) because a control character breaks cell width; the value is passed through byte-exact; with an icon field the icon is the last field and takes the remainder of the line, so a value containing a TAB needs `display<TAB>value` or a JSON mode. Why: the value is data the caller receives back and silently rewriting it is corruption, while display text has to fit a cell grid. Binds 06, 07, 15.
- 2026-11-16 — D16 Escaping at the pipe boundary: the default stays `display<TAB>value<TAB>icon`, and an opt-in pair `--in json` / `--out json` carries values byte-exact, including newlines, with JSON escaping doing the framing. Why: escaping on one side only moves the ambiguity to the caller, so input and output land together or not at all; `serde_json` is already in the tree for the spec adapter, so the cost is roughly 60 lines and a round-trip test rather than a new dependency. Binds 06, 07.
- 2026-11-16 — D17 Search text is a fourth item field, never a display trick, extending D12/D16: a line may carry `display<TAB>value<TAB>icon<TAB>search`, where `search` is matched and never drawn — rofi's drun matches Name, GenericName, Exec, Categories and Keywords while showing only the Name, which is why `seahorse` must find "Passwords and Keys". A hit found only through value or search scores a constant 1 (below every display match), is never highlighted (positions index the display) and keeps arrival order among peers, so a usage-ordered list stays usage-ordered. Why: the alternatives were to put those words in the display (then either they show, or the row lies) or to match the value alone (then Keywords and Categories are unreachable); this keeps the provider deciding what is searchable and the picker deciding how a hidden hit ranks. Binds 06, 07, 15.
